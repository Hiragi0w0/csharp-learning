# 職種マップ（該当度と根拠）

> 出典: 現在の業務領域と職種整理.pdf

## 現在の該当度

| 職種領域 | 該当度 | 根拠 |
|---|---|---|
| アプリケーションエンジニア / SE | ★★★★★ | C++製品の設計・実装・改修が現在も最大の業務 |
| プログラマー（PG） | ★★★★★ | C++、C#等で実装そのものを担当 |
| 社内SE / 業務改善SE | ★★★★☆ | 他部署要望を機能要件へ落とし、設計・開発まで担当 |
| AIアプリケーションエンジニア | ★★★★☆ | Dify、RAG、プロンプト、OpenAI API、AI組込開発 |
| ITアーキテクト | ★★★☆☆ | 技術候補選定、比較、PoC、方式設計、アーキテクチャ選定 |
| クラウドエンジニア | ★★☆☆☆ → ★★★☆☆ | Azure運用が中心だが、検証環境設計・VM / Blob構築へ拡大中 |
| インフラエンジニア | ★★★☆☆ | VM、Dify基盤、ログ、障害復旧、アップデート等 |
| SRE | ★★☆☆☆ | 障害復旧、更新検証、停止時間低減等は担当。ただしSLO / SLIや自動化はまだ薄い |
| セキュリティエンジニア | ★★☆☆☆ | CVE調査、影響判断、対応方針、アップデートまで担当 |
| PM / PL | ★☆☆☆☆ | 他人のタスク管理・チーム統括は基本的に担当していない |
| QAエンジニア | ★☆☆☆☆ | テストは行うが、QA専任ではない |
| MLエンジニア | ★☆☆☆☆ | モデル学習、Fine-tuning、MLOps等は担当していない |

## 見え方の整理

- **現在の主戦場**: アプリケーション開発（設計〜実装）と、AI・クラウド運用。
- **伸びている領域**: ITアーキテクト、クラウドエンジニア（検証環境設計・IaC方面）。
- **薄い / 未着手**: SLO・監視設計、CI/CD・自動化、QA専任、ML（学習・MLOps）。
- **意図的に持っていない**: PM / PL（タスク割り振り・人員管理・技術統括）。

## 伸ばす余地がある領域（学習テーマの候補源）

| 領域 | 現状 | 一歩先の到達点の例 |
|---|---|---|
| ITアーキテクト | 一部担当 | 方式設計の判断基準を言語化して説明できる |
| クラウド設計 | 入り始め | 検証環境をコードで作れる（IaC / CLI自動化） |
| SRE | 一部担当 | SLO/SLI を1つ決めて監視に載せられる |
| CI/CD | 未着手 | ビルド〜テスト〜配布を自動で回せる |
| セキュリティ | 運用の中で一部 | CVE対応を手順化して再現できる形にする |
| AIアプリ | 実務で担当 | RAGの精度評価を数値で語れる |
| QA / テスト | 実施はする | テスト設計を先に書く癖をつける |

> ★の数は「今の実態」であって、目標ではない。
> 上げたい領域は `learning-plan.md` で決める。
