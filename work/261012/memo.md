### 月 10/12：結果型を作る

1回の呼び出しの結果を、次の4つのどれかとして表す型を自分で設計する。

| 結果 | 持たせたい情報 |
|---|---|
| 成功 | 変換した値（`Item` など） |
| 見つからない（404） | なし、または ID |
| サーバーエラー（5xx） | ステータスコード |
| 接続失敗 | 理由（メッセージ） |

- 設計の候補は2つ。**推奨は (A)**。
  - (A) `abstract record` を親にして、4つの `record` を子として作る。`switch` 式で型ごとに分岐できる。
  - (B) `enum`（種類）と値をまとめた1つのクラス。C++ に近く書きやすいが、「成功なのに値が null」のような矛盾した状態を作れてしまう。
- (A) を選んだら、(B) で起こりうる矛盾を1つ、メモ欄に書く。
- この日は型を作るだけでよい。`ItemApiClient` はまだ変えない。

最小の形の例（**名前と中身は自分で決める**。このまま使わなくてよい）:

```csharp
public abstract record ApiResult<T>;
public record Success<T>(T Value) : ApiResult<T>;
// 残りの3つを自分で書く
```

**終わったと判断する目印:** 4つの結果を `switch` 式で受けて、それぞれ違う文字列を返す関数が書けて、ビルドが通る。

### 火 10/13：`ItemApiClient` を結果型で返すように書き換える

- `GetItem` を、`GetFromJsonAsync` から `GetAsync` ＋ `StatusCode` の分岐に書き換え、結果型を返す。
  - 成功したときだけ `ReadFromJsonAsync` で中身を変換する。
  - 接続失敗（`HttpRequestException`）は **`ItemApiClient` の中で** catch して結果型に変える。
- `GetAllItems`・`GetSlow`・`GetError` も同じ形にそろえる。
  - `GetSlow` の戻り値が `object` になっている。`{ "ms": 1000 }` を受ける型を自分で定義する。
- `Program.cs` から `try` / `catch` を消し、結果型の表示だけにする。
- 第2問の火曜分の表（404・500・接続失敗の表示）をここで満たす。

考えること（メモ欄に書く）:

- 例外を `ItemApiClient` の中で止めるのと、`Program.cs` まで流すのとで、呼ぶ側のコードはどう変わったか。
- タイムアウト（`OperationCanceledException`）も結果型に入れるべきか。入れる／入れない、どちらかに決めて理由を書く。

**終わったと判断する目印:** 存在しない ID を入れても、そのあとの `/slow` と `/error` が呼ばれて結果が表示される。
