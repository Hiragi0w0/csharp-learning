# 第2問：社員APIを呼び出すクライアント

`work/LearnApi01`（社員API）を **呼び出す側** のコンソールアプリを作る。
これまでは「リクエストを受ける側」を書いた。今回は「リクエストを送る側」を書き、通信が失敗する前提でコードを組む。

テーマとする技術:

- `HttpClient`: HTTPリクエストを送り、レスポンスを受け取るクラス。
- `async` / `await`: 通信の完了を待つあいだスレッドを止めないための書き方（非同期処理）。
- JSON の変換: `System.Net.Http.Json` の `GetFromJsonAsync` / `PostAsJsonAsync`。C# のオブジェクトと JSON を相互に変換する。
- ステータスコードによる分岐、タイムアウト、例外処理。

## 準備

- 社員API（`work/LearnApi01`）を `http` プロファイルで起動しておく。
  - `dotnet run --launch-profile http`。待ち受けURLは `http://localhost:5165`。
- クライアントは `work/261005/` に新しいコンソールアプリとして作る（`dotnet new console`）。
- 社員APIは起動直後のデータが空。データはクライアントから登録する。

## 仕様

クライアントは、次の手順を上から順に実行し、各手順の結果を1行以上表示する。

1. **登録**: 社員を3人 `POST /employees` で登録する。登録するデータはコード内に書く。
   - 成功（201）なら「登録しました: ID=…」と表示する。
   - 400 なら、レスポンス本文の `message` を表示する。
2. **一覧**: `GET /employees` で全件を取得し、「ID / 名前 / 部署 / 入社年」を1人1行で表示する。
3. **部署で絞り込み**: `GET /employees?department=…` で1つの部署の社員だけを取得して表示する。
4. **1件取得**: 存在するIDと存在しないIDの2つで `GET /employees/{id}` を呼ぶ。
   - 404 のときは例外で落とさず、「見つかりません: ID=…」と表示する。
5. **不正な登録**: 入社年が未来の年など、API側の検証で弾かれるデータを `POST` し、400 になることを表示で確認する。

失敗の扱い:

- サーバーが起動していない場合は、例外のスタックトレースをそのまま出さない。
  「サーバーに接続できません」と表示して終了する。
- タイムアウトは 5 秒に設定する。タイムアウトしたら、その旨を表示する。
- 2xx・400・404 以外のステータスコードが返った場合は、コードと理由を表示する。

## 設計の制約

- `HttpClient` はアプリ全体で **1つだけ** 作って使い回す（リクエストごとに `new` しない）。理由も調べる。
- API の呼び出しは専用のクラス（例: `EmployeeApiClient`）にまとめる。
  `Program.cs` のトップレベルには、手順 1〜5 の流れだけを書く。
- 社員データの型はクライアント側で自分で定義する（`record` 推奨）。
  JSON の項目名は API 側と同じにする（`iID`, `strName`, `strDepartment`, `iJoinedYear`）。
- `.Result` や `.Wait()` で非同期処理の完了を待たない。`await` を使う。

## 合格条件

- 社員APIが起動している状態で、手順 1〜5 が仕様どおりに表示される。
- 社員APIを止めた状態で実行すると、「サーバーに接続できません」と表示されて終了する（スタックトレースを出さない）。
- 次の失敗を、自分で起こして確認する。
  - 404（存在しないID）
  - 400（不正なデータ）
  - 接続できない（APIを止める）
  - タイムアウト（API側の1件取得に一時的に `await Task.Delay(10000);` を入れる。確認したら元に戻す）
- 以下を自分の言葉で説明できる。
  - `async` / `await` を使うと何がうれしいか。C++ でスレッドやコールバックを使って書く場合との違い。
  - `HttpClient` を使い回す理由。
  - 404 を「例外」として扱うか「戻り値」として扱うか、どちらにしたかとその理由。
  - `HttpRequestException` と `TaskCanceledException` が、それぞれどんな場面で投げられるか。

## やらないこと

- リトライ（再試行）や Polly などのライブラリ。今回は「失敗を正しく見分けて表示する」ところまで。
- 認証、HTTPS の証明書まわり（`http` プロファイルを使う）。
- DI（`IHttpClientFactory`）。名前だけ調べておけばよい。
