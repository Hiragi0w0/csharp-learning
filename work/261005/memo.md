# 第2問：作業ログの集計（日付つき）

第1問の続き。作業ログに日付の列が増えたCSVを読み、**担当者ごとの合計**と**日付ごとの合計**を表示するコンソールアプリ。

今回の練習ポイント:

- 同じキーの値をまとめる処理を、二重ループではなく `Dictionary<TKey, TValue>`（キーと値の対応表）または LINQ の `GroupBy`（キーごとにグループ化）で書く。
- 読み取り・検証・集計・表示を、それぞれ別のメソッドに分ける。
- 日付を文字列のまま扱わず、`DateOnly`（時刻を持たない日付型）に変換して扱う。

## 仕様

- 読み込むファイルのパスはプログラム内で指定する（コマンドライン引数は使わない）。
- 先頭行は見出しとして読み飛ばす。
- 各データ行は「日付,担当者名,作業時間」の3項目。日付の形式は `yyyy-MM-dd`（例: `2026-10-05`）。
- 前後の空白は取り除く。名前の大文字・小文字は区別する。
- 以下の行は不正として、行番号と理由を表示してスキップする。
  - 項目数が3つではない。
  - 日付が `yyyy-MM-dd` 形式の正しい日付ではない（`2026-02-30` や `2026/10/05` は不正）。
  - 担当者名が空。
  - 作業時間が整数ではない、または負数。
- 作業時間がゼロの行は有効。
- 出力は次の2つのブロックに分ける。
  1. **担当者別**: 合計時間の降順。同じ時間なら名前の昇順。
  2. **日付別**: 日付の昇順。
- 有効なデータが1件もない場合は「有効なデータがありません」と表示する。
- 指定したファイルが存在しない場合は、理由を表示して次のファイルへ進む。
- 引用符や項目内のカンマへの対応は不要。作業時間は int、合計は long に収まる前提。

出力例:

```text
## 01.csv
[担当者別]
Aki,50
Mika,45
[日付別]
2026-10-01,60
2026-10-02,35
```

## 設計の制約

- トップレベルの処理は「ファイルを順に処理する」流れだけにし、中身は次のようなメソッドに分ける（名前は自由）。
  - 読み取り: ファイルから行を読む
  - 検証・変換: 1行を検証し、正しければ1件分のデータにする
  - 集計: 担当者別・日付別の合計を作る
  - 表示: 結果を出力する
- 1件分のデータは `record`（値を入れるための簡潔な型）で表してみる。第1問の `class` + public フィールドとの違いを確認する。
- 担当者別の集計は `Dictionary` 版と `GroupBy` 版の**両方**で一度書き、どちらを採用するか理由を書く。

## 合格条件

- 上のルールどおりに集計・並べ替えできる。
- 不正な行が混ざっていても、後続の行を処理できる。
- 行番号は見出しを含めたファイル上の番号になる。
- 自分でテストデータを作る。少なくとも次のケースを確認する。
  - 合計時間が同じ担当者がいる
  - 項目数の不正
  - 存在しない日付（例: `2026-02-30`）と形式違いの日付（例: `2026/10/05`）
  - 有効なデータがない
- 読み取り・検証・集計・表示をどう分けたか、各メソッドが何を受け取り何を返すかを説明できる。
- `Dictionary` 版と `GroupBy` 版で、どちらを選んだかとその理由を説明できる。

`testdata/` に 01.csv〜 を自分で作る。期待する集計は先に手で計算してから照合する。
