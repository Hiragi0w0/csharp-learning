# 第2問：時間のかかる処理を並行して実行する（async / await）

時間のかかる処理（ダウンロードを想定）を複数実行するコンソールアプリ。
本物の通信は使わず、`Task.Delay` で「待ち時間」を作って代用する。

テーマとする技術:

- `async` / `await`: 処理の完了を待つあいだスレッドを止めないための書き方（非同期処理）。
- `Task` / `Task<T>`: 「いずれ終わる処理」と「いずれ得られる結果」を表す型。C++ の `std::future` に近い。
- `Task.WhenAll`: 複数の `Task` がすべて終わるのを待つ。
- `CancellationToken`: 実行中の処理に「中止して」と伝えるための仕組み。タイムアウトに使う。
- `Stopwatch`: 経過時間を測るクラス。

## 準備

- `work/261005/` に新しいコンソールアプリを作る（`dotnet new console`）。
- 外部のサーバーやファイルは使わない。

## 仕様

ジョブ（1件分の処理）は「名前・所要時間(ミリ秒)・失敗するかどうか」を持つ。一覧はコードの中に書く。

| 名前 | 所要時間(ms) | 失敗する |
|---|---|---|
| A | 1000 | しない |
| B | 1500 | しない |
| C | 500 | する |
| D | 2000 | しない |
| E | 4000 | しない |

ジョブ1件を実行する非同期メソッドを作る（例: `RunJobAsync`）。

- 所要時間のぶん `Task.Delay` で待ち、成功したら結果の文字列（例: `"A: 完了"`）を返す。
- 「失敗する」ジョブは、待ち終わったあとに例外を投げる。
- `CancellationToken` を受け取り、`Task.Delay` に渡す。

`Program.cs` では、次の3つを順に実行し、それぞれ **各ジョブの結果** と **全体の経過時間** を表示する。

1. **順番に実行**: 1件ずつ `await` して実行する。
2. **並行して実行**: 全件を一度に開始し、`Task.WhenAll` で完了を待つ。
3. **タイムアウトつきで並行実行**: 2 と同じ実行の仕方で、全体に 3 秒の制限をかける。3 秒を過ぎたジョブは中止する。

各ジョブの表示は次の3種類。

- 成功: `A: 完了`
- 失敗: `C: 失敗（理由）`
- 中止: `E: タイムアウトで中止`

1件が失敗または中止になっても、**ほかのジョブの結果は表示する**（全体を例外で落とさない）。

出力例（時間はおおよそ）:

```text
## 順番に実行
A: 完了
B: 完了
C: 失敗（…）
D: 完了
E: 完了
経過: 9.0 秒

## 並行して実行
...
経過: 4.0 秒
```

## 設計の制約

- `.Result` や `.Wait()` で完了を待たない。必ず `await` を使う。
- `async void` は使わない（戻り値は `Task` か `Task<T>`）。
- ジョブ1件分のデータは `record` で表す。
- 1件ごとの結果（成功／失敗／中止）は、例外のまま外へ流さずに型で表す。どう表すかは自分で決める。

## 合格条件

- 3つの実行の仕方それぞれで、各ジョブの結果と経過時間が表示される。
- 「順番」と「並行」で経過時間が違うことを確認し、数値の理由を説明できる。
  - 順番 ≒ 全ジョブの所要時間の合計（約9秒）
  - 並行 ≒ いちばん長いジョブの所要時間（約4秒）
- タイムアウトありでは、E だけが中止になり、その他は通常どおり終わる。
- 1件が失敗しても、ほかのジョブの結果が表示される。
- 以下を自分の言葉で説明できる。
  - `await` の行で何が起きているか。「スレッドを止めて待つ」こととの違い。
  - `Task.WhenAll` の待ち中に1件が例外を投げたとき、ほかの `Task` と例外はどうなるか（実際に試して確認する）。
  - `Task.Delay` と `Thread.Sleep` の違い。
  - C++ のスレッドや `std::async` で同じことを書く場合との違い。
- 自分で一覧を書き換えて追加のケースを試す。少なくとも「全件成功」「全件失敗」「全件タイムアウト」を確認する。

## やらないこと

- `HttpClient` を使った本物の通信（次の段階）。
- `Parallel.For` や `Task.Run` を使った CPU 処理の並列化。今回は「待ち時間の重ね合わせ」だけ。
- リトライ（再試行）。
