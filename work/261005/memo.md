# 第2問：HttpClient で API を呼び出す（10/5 月 〜 10/9 金）

最小の ASP.NET Core サーバー（呼ばれる側）と、それを `HttpClient` で呼び出すコンソールアプリ（呼ぶ側）を作る。
**学習の中心は呼ぶ側。** サーバーは、決まった応答を返すだけの最小限にする。

テーマとする技術:

- `HttpClient`: HTTP リクエストを送り、レスポンスを受け取るクラス。
- JSON の変換: `System.Net.Http.Json` の `GetFromJsonAsync` / `ReadFromJsonAsync`。JSON と C# のオブジェクトを相互に変換する。
- ステータスコードと例外: 404・500・接続失敗を見分ける。
- `async` / `await`: 処理の完了を待つあいだスレッドを止めないための書き方（非同期処理）。
- `Task.WhenAll`: 複数の `Task`（いずれ終わる処理）がすべて終わるのを待つ。
- `CancellationToken`: 実行中の処理に「中止して」と伝える仕組み。タイムアウトに使う。

## サーバーの仕様（作るのはこれだけ）

商品データ（`Id`, `Name`, `Price`）を3件、コードの中に固定で持つ。

| エンドポイント | 応答 |
|---|---|
| `GET /items` | 全件を JSON で返す（200） |
| `GET /items/{id}` | 該当する1件（200）。なければ 404 |
| `GET /slow?ms=1000` | 指定したミリ秒だけ `Task.Delay` で待ってから、`{ "ms": 1000 }` を返す（200） |
| `GET /error` | 500 を返す |

### 月 10/5：サーバーと HttpClient の基本

- サーバーを作る。ブラウザか curl で4つのエンドポイントの応答を確認する。
- クライアントで `GET /items` と `GET /items/{id}`（存在する ID）を呼び、結果を表示する。
- 商品データの型はクライアント側で自分で定義する（`record`）。
- `HttpClient` はアプリ全体で **1つだけ** 作って使い回す。

**終わったと判断する目印:** クライアントを動かすと、一覧と1件が表示される。

### 火 10/6：失敗を見分ける

次の3つを実際に起こし、例外で落とさずに見分けて表示する。

| ケース | 起こし方 | 表示 |
|---|---|---|
| 404 | 存在しない ID を指定する | `見つかりません: ID=…` |
| 500 | `GET /error` を呼ぶ | `サーバーエラー: 500` |
| 接続失敗 | サーバーを止めてからクライアントを動かす | `サーバーに接続できません` |

- 呼び出しは `GetAsync` で `HttpResponseMessage`（レスポンス全体）を受け取り、`StatusCode` を見て分岐する。成功したときだけ `ReadFromJsonAsync` で中身を変換する。
- 比較のため、同じ 404 と 500 を月曜の `GetFromJsonAsync` でも呼んでみる。2つの書き方で、**例外が投げられるのか、ステータスコードとして返ってくるのか** を、先に予想してから確かめる。接続失敗についても同じように予想する。
- 1回の呼び出しの結果（成功／見つからない／サーバーエラー／接続失敗）を、例外のまま外へ流さずに型で表す。どんな型にするかは自分で決める。

**終わったと判断する目印:** 3つの失敗が、スタックトレースを出さずに見分けて表示される。

### 水 10/7：並行実行とタイムアウト

次の5つの呼び出しを、3通りの方法で実行する。各呼び出しの結果と全体の経過時間（`Stopwatch` で測る）を表示する。

| 名前 | 呼び出し |
|---|---|
| A | `/slow?ms=1000` |
| B | `/slow?ms=1500` |
| C | `/error` |
| D | `/slow?ms=2000` |
| E | `/slow?ms=4000` |

1. **順番に実行:** 1件ずつ `await` する。
2. **並行して実行:** 全件を一度に開始し、`Task.WhenAll` で待つ。
3. **タイムアウトつきで並行実行:** 2 と同じ方法で、全体に 3 秒の制限をかける（`CancellationTokenSource`）。

**終わったと判断する目印:**

- 順番は約 8.5 秒（全件の合計）、並行は約 4 秒（いちばん長い E）になる。
- タイムアウトありでは E だけが中止になり、それ以外は通常どおりの結果になる。
- C が失敗しても、ほかの結果は表示される。

### 木 10/8：崩して確かめる

動いているコードを1か所ずつ変えて、何が起きるかを確かめる。確かめたら元に戻す。

- 並行実行の書き方を変えて、経過時間を比べる。先に予想を書いてから試す。
  - (a) 1件呼び出すたびに、すぐ `await` する（呼び出しの開始が1件ずつずれる）。
  - (b) 5件ぶんの `Task` を先に全部作り、そのあと1件ずつ `await` する（`Task.WhenAll` は使わない）。
  - `Task.WhenAll` は処理を開始するものではなく、「渡した `Task` がすべて終わる」ことを表す `Task` を作るだけ。経過時間を決めるのは、**いつ呼び出しを開始したか** であることを確かめる。
- `await` の代わりに `.Result` を使う。
- `HttpClient` を、リクエストのたびに `new` する。
- `Task.WhenAll` の中の1件が例外を投げたとき、ほかの `Task` と例外がどうなるかを確かめる。
- `HttpClient.Timeout` と `CancellationToken` のどちらでタイムアウトさせても、結果は同じになるか。

## 書き方の決まり

- `.Result` や `.Wait()` で完了を待たない（木曜に試すときだけ例外）。
- `async void` は使わない（戻り値は `Task` か `Task<T>`）。
- API を呼び出す処理は専用のクラス（例: `ItemApiClient`）にまとめる。`Program.cs` のトップレベルには流れだけを書く。

## 合格条件（説明できること）

- `HttpClient` を使い回す理由。
- 404 と 500 は例外になるか、ステータスコードとして返るか。`GetAsync` と `GetFromJsonAsync` で何が違うか。接続失敗はどうか。
- `HttpRequestException` と `TaskCanceledException` が、それぞれどんな場面で投げられるか。
- `await` の行で何が起きているか。「スレッドを止めて待つ」こととの違い。
- 順番と並行で経過時間が違う理由。
- C++ のスレッドや `std::async` で同じことを書く場合との違い。
